---
title: Build your app for Android and iOS
description: Compile your Duddy project into an Android APK or an ad hoc iOS app. Choose a target, follow the build console, install the file and see what builds cost.
---

A *release build* turns your project into a standalone app file that you can install and share.
Duddy writes native source for the platform you choose and compiles it with that platform's own
toolchain: Gradle for Android, and Xcode on a Mac for iOS.

You do not need a release build to try your app while you design. [Live test](/build/live-test)
runs the project on your phone and follows every edit, for free. Build when you want a file to keep,
install or send to someone.

## Before you build

Open **Settings → Project** in the designer and check these fields. They are explained in full
on [Project settings](/getting-started/project-settings).

- **App name**, **Version code** and **Version name**. The version code is a whole number that
  must rise with every store upload.
- **Package name**, such as `com.yourcompany.yourapp`. Choose it as if it is permanent, because
  once an app is on a store, it is. An iOS build is refused without one. An Android build made
  without one gets a placeholder, `com.duddy.` followed by your app name, which is not a name you
  want to publish under.
- **Target platforms**. A build for a platform that is switched off is refused with "This app is
  not built for iOS. Turn iOS on under Target platforms in Project settings to build it." (or the
  same sentence for Android).

An iOS build also needs a plan that includes iOS builds and an Apple Developer key connected to
your account. [iOS builds](/build/ios-builds) lists everything it needs.

You need write access to the project. For a read-only collaborator the **Build** button is greyed
out, with the tooltip "Read-only: Building disabled".

## Choose a build target

To build an Android `.apk` or an iOS app, press **Build** at the top right of the designer, or
press `Ctrl` + `B` (`⌘` + `B` on a Mac), and choose a target. The shortcut only opens the menu; it never starts a build on its own.

| Menu item | Group | What you get |
|---|---|---|
| **Android App (.apk)** | Android | A signed `.apk` that installs on any Android phone. Install it yourself or send it to testers. |
| **Android App Bundle (.aab)** | Android | Coming soon. Google Play needs this format for new apps. Choosing it says "This part of the builder is still being built." |
| **iOS App (.ipa)** <Badge type="beta" /> | Others | An ad hoc `.ipa`, signed with your Apple key, that installs on iPhones registered to your Apple Developer account. |
| **Web App (coming soon)** | Others | Coming soon. Opens a page where you can press **Notify me** to hear when web builds arrive. |

An Android build starts as soon as you choose it. An iOS build checks your Apple setup first; see
[iOS builds](/build/ios-builds).

## Follow the build console

The **Console** opens as soon as a build starts. It lives in the left rail of the designer, as
the terminal icon near the bottom, and a dot on that icon shows the state of the latest build. You
can close the console and keep designing while the build runs.

The pill at the top right of the console shows one of three states:

| State | Means | What to do |
|---|---|---|
| **Building** | Duddy is writing your app's source and compiling it. Quiet stretches are normal: after three minutes the console says "Large builds can take several minutes. Nothing is stuck." | Wait, or close the console and keep working. |
| **Ready** | The app compiled. The console shows its version, package name, SDK levels and a preview of the entry screen. | [Install it](#install-the-app-on-a-phone) within the hour. |
| **Failed** | The build stopped. The last line of the log says what went wrong and what to do. | Find the message in [Fix a failed build](/build/troubleshoot-builds). |

The line under the console's title is the build ID. Quote it if you report a problem. The two
buttons beside **Build log**, **Copy logs** and **Download logs**, keep a copy of the log once the
build has finished.

Amber lines in the log are notices. They tell you about something the build adjusted or left out,
such as an entry screen that no longer exists, without stopping it.

## Install the app on a phone

When the console says **Ready**, its **Install this build** panel offers three ways to get the app:

- Scan the QR code with the phone's camera to download the app straight onto the phone.
- **Download app** saves the `.apk` or `.ipa` file to your computer.
- **Copy link** copies the file's download link.

<Callout type="warning" title="Download it within the hour">
  A release build's file and its link last one hour. After that, the link answers "This download
  link has expired. Build the app again to get a new one." Download the file if you want to keep it.
</Callout>

**On Android**, open the `.apk` on the phone. The first time you install an app from a browser or
a file manager, Android asks you to allow installs from that app.

**On iPhone**, scan the QR code with an iPhone that is registered to your Apple Developer account.
An ad hoc build does not install on any other iPhone. See
[iOS builds](/build/ios-builds#install-the-build-on-an-iphone).

To send the app to other people, see [Share and publish](/build/share-and-publish).

## Test it live on a device

Live test puts a *test app* on your phone: your own app, with your name and icon, that connects to
the designer and draws your project as you edit it. You build the test app once, and from then on
changes to screens, logic and theme reach the phone without another build. Test builds are free.

## What a build costs

Release builds within your plan's hourly build limit are free. The limit counts the builds of
every project on your account, and the hour starts with your first build rather than on the
clock.

Past the limit, a build costs credits, and Duddy asks before charging anything. A dialog titled
**This build costs credits** says "You've used this hour's builds." and names the price. Press
**Build** to pay it, or **Cancel**; the console then says "Build cancelled — no credits were
spent." The price depends on your plan: see [Plans and limits](/account/plans-and-limits), and
[Credits](/getting-started/credits-and-plans) for how your balance works.

- **Live test builds are free.** They never cost credits and do not count towards your hourly
  limit.
- **A refused build costs nothing.** A build stopped by a check, such as the iOS checklist or a
  missing build worker, is refused before it is priced.
- **Trial builds carry Duddy branding.** Apps built on the free trial open on a Duddy splash
  screen when they have no splash image of their own, and Android apps show a **Made with Duddy**
  badge. Builds made on a paid plan carry neither.

## Build for iOS

<Badge type="beta" /> iOS builds are in beta. An iOS build gives you an ad hoc `.ipa` that installs over the air on the
iPhones registered to your Apple Developer account. It needs:

- a plan that includes iOS builds (the free trial and Pro do; Starter does not)
- an App Store Connect API key, connected as described in [Apple](/integration/apple)
- your package name registered with Apple as a Bundle ID
- at least one registered iPhone, running iOS 26 or later

The first time you choose **iOS App (.ipa)**, a **Beta Feature** notice appears. After you press
**Proceed**, a checklist titled **Before we build for iOS** checks your Apple setup before
anything is spent. Duddy does not upload builds to TestFlight or App Store Connect.
[iOS builds](/build/ios-builds) covers each check, Mac build workers and installing on an
iPhone.

## Web builds and hosting

Web builds are coming soon. Compiling a project to a web app, and putting it online from
**Settings → Hosting**, exist behind the scenes but stay switched off until every generated app
runs reliably. Choose **Web App (coming soon)** in the Build menu and press **Notify me** to get
one email when web builds turn on. Web builds will read the same project you build for Android
today.

## When a build fails

A build that cannot start is refused with a message, and the console shows **Failed**. A build
that fails part-way ends with a sentence that says whose problem it is (your project, the build
server or Duddy's own code) and what to do. [Fix a failed build](/build/troubleshoot-builds)
lists every message and its fix.
