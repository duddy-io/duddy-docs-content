You have arrived here from a component in the builder. The full reference is organised by
the same categories as the component palette:

<CardGrid>
  <Card title="Layout" href="/components/layout">Screen, Row, Column, Stack, TopBar, cards, tabs, sheets and dialogs.</Card>
  <Card title="Content" href="/components/content">Text, images, icons, shapes, lists and progress.</Card>
  <Card title="Input" href="/components/input">Buttons, fields, switches, sliders and pickers.</Card>
  <Card title="Media" href="/components/media">Video, audio, camera, speech and animation.</Card>
  <Card title="Connectivity" href="/components/connectivity">HTTP, WebSocket, maps, web views and network state.</Card>
  <Card title="Storage" href="/components/storage">Key-value storage, SQLite, files and the clipboard.</Card>
  <Card title="Firebase" href="/components/firebase">Auth, databases, storage, messaging and analytics.</Card>
  <Card title="Sensors" href="/components/sensors">Motion, location, proximity, haptics and scanning.</Card>
  <Card title="Ads" href="/components/ads">AdMob and Meta Audience Network placements.</Card>
  <Card title="Everything else" href="/components/other">Device info, sharing, calls, purchases and utilities.</Card>
</CardGrid>

<Callout type="info">
  Every component page lists the component's **events** (what it tells your logic about) and its
  **functions** (what your logic can tell it to do). Those are the blocks you get in the block
  editor once the component is on a screen.
</Callout>

Start at the [component overview](/components/overview) if you would rather read about how
components work before looking one up.
