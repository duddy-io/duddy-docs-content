Components are the pieces an app is made of. Some draw something — a button, an image, a
list. Some draw nothing and exist purely to do a job — call an API, store a value, read the
device's location.

Every component is native code on each platform, so a Duddy app is built from real platform
widgets rather than a web page pretending to be one.

## Three surfaces

Every component exposes the same three kinds of thing, and they are what you work with in
the designer and the block editor.

| | Where you use it | Example |
|---|---|---|
| **Properties** | The properties panel, and get/set blocks. | A button's `Text`, a container's `Background`, a switch's `Checked`. |
| **Events** | The block editor — a hat block you put actions inside. | `Click`, `Text Changed`, `Got Response`, `Location Changed`. |
| **Functions** | The block editor — an action you call. | `Show`, `Play`, `Make Request`, `Store Value`. |

Drop a component onto a screen and its blocks appear in the block editor's toolbox under
its name.

## Visual and logic-only

A **visual** component has a box on the canvas that you size, position and style. A
**logic-only** component has none: drag it anywhere onto the screen and it joins the screen
as a component you can address from blocks. `HttpRequest`, `AppStorage` and `Clock` are
logic-only; they never show up in the layout.

<Callout type="info">
  A property row that disappears when you change another one is the component saying it does not
  apply right now — an ad banner does not offer padding, a slider offers no text alignment.
</Callout>

## Imported components

Alongside the components Duddy ships, a project can import components published by other
developers. An imported component behaves exactly like a built-in one: it has properties,
events and functions, and it appears in the palette and the block toolbox in its own
category.

<Callout type="info">
  A component's identity is its full name — `io.duddy.components.Button`. That is what a project
  stores, so a component keeps working the same way in every project that imports it.
</Callout>

## Reading these pages

Each category page lists its components with what the component does, whether it draws
anything, its events and functions, and any Android permission it needs. Properties are not
listed page by page: the properties panel in the designer always shows exactly what the
component you have selected supports, which is the one list that can never be out of date.
